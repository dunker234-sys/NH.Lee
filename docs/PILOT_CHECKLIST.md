# PILOT_CHECKLIST — 파일럿 투입 전 체크리스트

STEP12 운영 문서. `ROADMAP.md`의 "파일럿 전 반드시 할 것(부록 B)"을 실행
가능한 체크리스트로 승격한 것이다. 실제 사업장 1~2곳에 시스템을 투입하기
전, 아래 항목을 **전부** 완료·기록해야 한다.

## 1. 계산 정확도 검증

- [ ] 실제 사업장 1~2곳의 **지난달** 근태 데이터로 계산 엔진 결과를 수기
      집계와 대사(reconciliation) — **목표 일치율 99% 이상**
  - 불일치 건이 있으면 원인을 분류해 기록한다: (a) 계산 엔진 버그,
    (b) 수기 집계 쪽 오류, (c) Phase 0 노무 검토 확정 사항과 현장 관행의
    괴리(예: 미승인 연장 처리 방식에 대한 현장의 암묵적 기존 관행).
  - 99% 미만이면 원인 (a)를 우선 해소하고 재대사한다. (c) 유형이면 노무
    검토(§2)로 넘겨 정책 확정 여부를 다시 확인한다.

## 2. 법률·노무 검토

- [ ] 노무사 검토 완료 — 미승인 연장근로 처리(v2: 전량 산입+검토 플래그),
      근로일 귀속(v2: 시업일 귀속+휴일 판정 역일 분할), 휴게시간 처리(v2:
      자동 공제 금지), 퇴근 미등록 시 계획 시각 자동 적용(v2: 기본 비활성)
      — **Phase 0에서 확정한 4가지 기준이 실제 계약서·취업규칙과 충돌하지
      않는지** 재확인
- [ ] 단시간 근로자 소정근로 초과분 규율 검토
- [ ] 법무 검토 완료 — 위치정보 수집·이용 동의 문구, 위치기반서비스사업
      신고 대상 여부, 연차 촉진 통지의 "서면" 요건에 전자적 방법(앱/이메일)
      포함 여부
- [ ] 시행 예정 법령 대조 — 2026.8.20 / 2026.10.8 / 2026.12.10 / 2027.1.1 /
      2027.6.10 시행 개정본이 계산 규칙(`packages/core-rules`)에 영향을
      주는지 확인, 영향이 있다면 `policy_config` 수치 변경만으로 대응
      가능한지 코드 변경이 필요한지 판단

## 3. 현장 운영 준비

- [ ] 노사 협의 완료(파일럿 사업장 대상)
- [ ] 현장 관리자 교육 — `docs/ADMIN_MANUAL.md` 기준, 최소 미승인 실적
      판정·정정 승인·마감 제출 3가지 실습 포함
- [ ] 근로자 안내 배포 — `docs/WORKER_QUICK_GUIDE.md`(인쇄물 또는 앱 첫 화면),
      다국어(ko/en/vi) 버전 확인
- [ ] 키오스크 기기 현장 등록 및 PIN 배포 완료
- [ ] 사업장 IP allowlist(PC 웹 타각용) 등록 완료 — 비어 있으면 fail-closed
      이므로 등록 누락 시 PC 웹 타각 자체가 전부 막힘에 유의

## 4. 파일럿 기간 중 모니터링 지표 (최초 2~4주)

아래 지표는 `docs/INCIDENT_RUNBOOK.md`의 상시 운영 지표와 별개로, **파일럿
품질 판단용**으로 별도 집계한다.

- [ ] **지오펜스 오탐률** — 실제로는 정상 출근인데 지오펜스 이탈로 판정된
      비율. 목표치는 파일럿 착수 시 현장 특성(반경 설정값)을 보고 별도 협의
      — 급식 현장은 건물 구조상 GPS 오차가 큰 경우가 있어 사전 반경 튜닝이
      필요할 수 있다.
- [ ] **오프라인 큐 전송 성공률** — 모바일/키오스크에서 오프라인 저장된
      타각이 재연결 후 정상 전송(중복 없이)되는 비율. 목표: 100%에 근접
      (`test/kiosk-offline-recovery.e2e-spec.ts`가 검증하는 "재전송해도
      1건만 남음" 보장이 실제 현장 네트워크 환경에서도 성립하는지 확인).
- [ ] **계산-수기 대사 일치율** — §1과 동일 기준을 파일럿 **진행 중** 데이터로
      매주 재확인(초기 1회성 검증이 아니라 지속 확인). 목표 99% 이상 유지.
- [ ] **미승인 실적 발생률 및 판정 소요시간** — 판정까지 걸리는 평균 시간을
      추적한다. 소요시간이 계속 길어지면(검토 큐 적체) 관리자 알림/교육
      보강이 필요하다는 신호다.

## 5. 배포·복구 준비 상태 확인

- [ ] 부하 테스트 통과 확인(P95 1초 이내) — 근거:
      `apps/api/test/punch-load-performance.e2e-spec.ts` 실행 로그
- [ ] 위치정보 파기 배치 정상 실행 확인 — 근거:
      `apps/api/test/punch-location-retention.e2e-spec.ts` +
      `retention-job-role-boundary.e2e-spec.ts` 실행 로그, 실 운영 첫 배치
      1회 실행 후 `audit_log`의 `PUNCH_LOCATION_PURGED` 이벤트 확인
- [ ] RTO 4시간 이내 복구 절차 검증 완료 — 근거: `docs/DISASTER_RECOVERY.md`
      실측 결과(로컬 드릴). **실 클라우드 환경 전환 시 동일 절차로 재검증
      필요**(로컬 드릴은 절차 검증이지 클라우드 다중AZ 페일오버 검증이
      아님)
- [ ] Terraform IaC `plan` 결과 검토 완료(`infra/terraform/README.md`의
      "apply 전 실값으로 채워야 하는 변수" 표 전항목 확정)

## 6. 파일럿 종료 후 다음 단계 판단 기준

모든 항목 체크 완료 + §4 지표가 목표치를 충족하면 확대 적용을 검토한다.
목표치 미달 항목이 있으면 해당 항목만 별도 개선 스프린트로 분리하고,
전사 확대는 보류한다.
