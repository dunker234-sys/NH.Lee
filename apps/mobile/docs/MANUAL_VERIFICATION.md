# MANUAL_VERIFICATION — STEP 5-A 완료조건 수동 검증 절차

이 문서는 자동화로 완전히 대체할 수 없는 검증 시나리오를 다룬다(계획서
§10.2). CLAUDE.md §6("완료조건에 명시된 시나리오는 테스트로 자동화하며,
수동 확인으로 대체하지 않는다")보다 느슨한 예외이며, 이유는 명확하다 —
"사용자가 직접 강제종료한 앱은 iOS가 백그라운드로 깨우지 않는다"는 OS
레벨 동작 자체가 이번 완료조건의 전제이고, 이건 시뮬레이터/CI 환경에서
완전히 재현할 방법이 없다.

자동화된 부분(먼저 확인):
- `apps/mobile/src/offline/__tests__/punchQueueLogic.test.ts` —
  재전송 시 페이로드 불변성, 상태 전이, 멱등키 구성요소 보존을
  node:sqlite로 실제 SQL 엔진 위에서 검증(9개 테스트).
- `apps/mobile/src/offline/__tests__/flushLogic.test.ts` — 단일/벌크 전송
  선택, 서버 응답→큐 상태 매핑, 실패 시 재시도 마킹을 페이크 API로
  검증(7개 테스트).
- `apps/api/test/{sites,consent,alert-log,location-access-log}.e2e-spec.ts` —
  이번 STEP이 추가한 백엔드 4종의 self-scoping·정책값 서버 해석을 실제
  Postgres+Redis로 검증(완료).

아래는 실기기 또는 EAS dev client 시뮬레이터 빌드가 준비된 뒤 수행한다.
**EAS 계정 자격증명(Apple Developer/Firebase)이 아직 없다면 이 문서의
시나리오는 착수할 수 없다** — 계획서 §11-1 참고.

## 1. 완료조건1: 비행기모드 타각 → 강제종료 → 재실행 → 복구 시 자동전송, 서버 1건만 저장

**사전 준비**: `apps/api`를 실제 실행(로컬 또는 스테이징), 앱을 그 API를
가리키도록 빌드(`EXPO_PUBLIC_API_BASE_URL`), 테스트 계정으로 로그인 완료.

| 단계 | 조작 | 기대 상태 |
|---|---|---|
| 1 | 기기를 비행기모드로 전환 | 네트워크 끊김 표시 |
| 2 | 홈에서 "출근" 1탭 | 즉시 완료 피드백(햅틱+배너) 표시, 홈 헤더에 "1건 대기중" |
| 3 | 앱 스위처에서 앱을 위로 스와이프해 강제종료(단순 백그라운드 아님) | 프로세스 완전 종료 |
| 4 | 앱 재실행 | 재실행 직후 자동으로 플러시 시도(오프라인이라 실패 유지) |
| 5 | 비행기모드 해제 | 몇 초 내 자동 전송, 홈 헤더가 "동기화됨"으로 전환 |

**검증 쿼리**(apps/api가 물린 DB, `psql` 또는 Prisma Studio):
```sql
SELECT id, punch_type, recorded_at, device_id
FROM punch_raw
WHERE employee_id = '<테스트 직원 id>'
  AND recorded_at >= '<2단계 시각 -1분>'
ORDER BY recorded_at DESC;
```
정확히 1행이어야 한다. 여러 행이 있으면 실패 — `recordedAt`이 재전송마다
바뀌었거나(재계산 버그) 서버 멱등키 해시가 기대와 다르다는 뜻이다.

## 2. 완료조건2: 위치 동의 거부 시에도 앱 동작 + 대체수단 안내

| 단계 | 조작 | 기대 상태 |
|---|---|---|
| 1 | 최초 실행(또는 앱 데이터 초기화) → 로그인 | `ConsentGateScreen` 표시 |
| 2 | "동의하지 않음" 탭 | MainTabs 진입(차단되지 않음) |
| 3 | 홈에서 "출근" 탭 | GPS 권한 팝업이 **뜨지 않아야** 한다(다크패턴 방지) — `PunchScreen`으로 이동 시 상시 배너로 "NFC 태깅 또는 QR 스캔... 키오스크..." 안내 표시 |
| 4 | 배너의 스캔 버튼 탭 | `ScanScreen`으로 이동 |

## 3. 완료조건3: 일시중지 버튼 → 위치수집 중단 + 서버 이력

| 단계 | 조작 | 기대 상태 |
|---|---|---|
| 1 | 개인정보 화면(⚙️ 아이콘) 진입, 위치 동의 상태가 "동의함"인지 확인(아니면 먼저 동의) | — |
| 2 | "위치정보 수집 일시중지" 탭 | 상태가 "일시중지됨"으로 즉시 갱신, 이력 목록에 새 행 추가 |
| 3 | 타각 시도(GPS) | 완료조건2와 동일하게 NFC/QR 유도 배너 표시 |
| 4 | 서버 DB 확인 | `SELECT * FROM consent WHERE employee_id=... ORDER BY created_at DESC` — `status='PAUSED'`, `paused_at` 채워진 행이 최신에 있어야 한다 |

## 4. 생체인증 재로그인

Simulator: iOS Simulator의 Features → Face ID/Touch ID → Enrolled 활성화 후
Matching/Non-matching Touch로 근사 가능. 실기기는 실제 Face ID/지문 등록
필요.

1. 비밀번호로 최초 로그인 → "생체인증으로 로그인하시겠어요?" 프롬프트에서 "사용할게요" 선택.
2. 앱 완전 종료 후 재실행 → `BiometricGateScreen`이 자동으로 생체인증을 요청.
3. 인증 성공 → MainTabs 진입(비밀번호 재입력 없음).
4. 인증 실패/취소 → "다시 시도" 또는 비밀번호 로그인으로 폴백 버튼 확인.

## 5. NFC — 시뮬레이터로 검증 불가, 실기기 필수

iOS/Android 시뮬레이터·에뮬레이터에는 NFC 하드웨어가 없다. `ScanScreen`의
NFC 경로는 실기기에서만 검증 가능하다. 또한 사업장 QR 코드가 정적
스티커가 아니라 TOTP를 실시간 렌더링하는 표시 장치여야 하므로(계획서
§6), QR 경로의 end-to-end 검증은 STEP 5-B/6에서 그 표시 장치가 갖춰진
뒤에만 가능하다 — 지금은 `ScanScreen`이 QR 페이로드를 올바르게 디코드해
`qrOrNfcToken`으로 전달하는지까지만 확인할 수 있다.

## 6. 홈 진입~타각 완료 2탭 이내(완료조건4)

계획서 §1의 설계상 일반 경로는 **1탭**(홈의 출근/퇴근 버튼)이다. 스톱워치
없이도 "홈 화면 도착 후 첫 번째 탭에서 완료 피드백(햅틱+배너)이 뜨는가"만
확인하면 된다 — 두 번째 경로(PunchScreen 경유)도 2탭을 넘지 않는지 함께
확인한다.
